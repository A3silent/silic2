# Crystal 内部模型掩体（2026-10-17）

状态：历史阶段，已被后续[巨型模型墙体修订](crystal-megastructure.md)取代。
以下保留上一轮低掩体实现与验收记录，不代表当前地图摆放。本轮是 Tripo 资产接入后的追加修改；用户要求部分船体、骨架和水晶
进入竞技场内部，作为有实际碰撞的掩体及装饰。

## 范围

复用已经生成的模型与贴图，不调用Tripo、不新增额度消耗。外部大型残骸地标及新步枪
保留。已把南侧、东侧旧低掩体分别替换为船体残片和骨肋，在两个有绕行空间的位置
加入小型水晶簇。

视觉网格与简化碰撞代理分离，通过既有 `collisionAsset` 使用相同实例变换。
玩家、敌人、玩家射击、敌方投射物及视线查询共享空间数据；不单独增加一套掩体规则。
实体要阻挡，明显骨缝要保留，不以整件模型的包围盒制造空气墙。主通道、坡口、
桥下净空、出生点和敌人绕行受保护；必要的导航连接调整由VECTOR核对后交NEBULA落地。

## 分工与验收

NEBULA独占地图和新增内部道具/代理资源；VECTOR负责空间查询、碰撞/导航/开口与
普通输入测试、构建和功能整合；ATLAS负责范围、协调与实际图片/日志复核。
保留此前未提交工作。角色、武器、音频、Hollow表现与射击/移动数值不在本轮修改范围。

验收覆盖各类掩体的实体/开口射线、移动阻挡和滑铲、敌人绕行与高处可攻击性、
出生点安全、编辑器加载/保存及普通路线巡行。
用户明确本轮不做性能测试：取消长时实战性能采样、帧时间CSV及性能基准；
短时GL仅用于摆放和碰撞功能目视检查。
自动化与相机预览不替代人工手感和可读性试玩。

基线及最终证据保存在 `artifacts/acceptance/tripo-interior/`。

## 首轮功能观察

四类实例的实体双向LOS/敌弹、正常移动与滑铲非穿入、真实Chaser地面绕行通过。
北/南水晶挡住4条旧导航边，已删除这些穿过新实体的边，导航图保持连通。
每件1092条截面射线用于量化视觉与代理差异，不把采样当成连续几何精确证明。

额外发现站在低掩体顶部时Chaser可能停止追逐。VECTOR用原31/32掩体对照后确认
旧地图同样出现，四件新掩体的地面目标绕行正常。本轮不修改敌人导航策略，
不宣称消除了站顶安全点；保留该既有问题作为后续AI改进项。
