# Crystal Combat modules

Original deterministic Silic2 geometry, generated by
`tools/environment/generate_crystal_combat.py`. No imported third-party artwork.
OBJ uses metre-scale coordinates, Y up and outward triangle winding. Materials
belong to map instances, so these meshes work with the shared static OBJ subset.
Visual and collision assets are the same file in the first battle map. The open
vault and gaps beneath the curved bridge therefore remain real collision openings.

| Module | Local dimensions / placement |
| --- | --- |
| ring_deck_30 | Inner radius 12, outer 18; 30° sector; top Y=0, bottom −0.8. Six rotated instances at Y=6 form the north half ring. |
| ramp_6x22 | Width 6; local Z −11 crest Y=6, Z +11 foot Y=0. Battle map scales Z by 15/22 and places at Z=7.5: exact crest Z=0, foot Z=15. |
| curved_wall_45 | Inner radius 28, outer 29.4; 45° closed sector, base Y=0, height 7 before instance scale. Eight differently scaled instances form the visible outer shell. |
| leaning_support | Height 11, base 2.2×2.2, top displaced 4.2 along +X. |
| crystal_shell | One asymmetric solid shell with broad facets and a capped top; the central tactical obstruction. |
| crystal_vault | Seven thick arch panels; open through both Z ends, local width 13.6 and depth 8. The central opening is not filled by a collision box. |
| low_cover | Low inclined block, width 4, height 1.2, depth 1.6. |

`manifest.json` lists exact generated bounds and triangle counts. Assets have no
runtime Python dependency. The companion map authoring script is
`tools/environment/build_crystal_combat_map.py`; it generates only the selected
Crystal map, using explicit three-dimensional nodes and links. It is an authoring
recipe, not the collision or navigation implementation. Run the game's public
Map/SpatialWorld diagnostics and real actor checks after changing it.
