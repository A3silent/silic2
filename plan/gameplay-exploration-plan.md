# Silic2 玩法探索计划

## 1. 结论

Silic2 最有潜力的方向不是把四款参考游戏的功能叠加，而是建立一套职责清楚的设计组合：

| 参考作品 | 借鉴的核心职责 | 不直接照搬的部分 |
|---|---|---|
| Devil Daggers | 高压战斗、移动即生存、固定威胁节奏、失败可学习 | 一击即死、单一永久竞技模式 |
| Eclipsium | 空间异变、感官叙事、低保真视觉的功能性、声音引导 | 低互动步行模拟、线性四小时流程 |
| 元气骑士 | 短房间节奏、武器发现、模块化随机地牢、局内资源决策 | 数百件武器、角色商业化与长期数值膨胀 |
| Vampire Survivors | 可叠加构筑、指数式火力成长、时间导演、持续奖励反馈 | 自动攻击、纯粹割草、强制 30 分钟局长 |

推荐的一句话定义是：

> **一款主动瞄准、高速移动的第一人称压力型 roguelite；玩家穿过不断异变的短房间，在可学习的敌潮中拾取危险区域里的能量，并把基础武器构筑成失控但仍需技巧驾驭的杀戮机器。**

这一定义保留了项目现有的 FPS、滑铲、跳跃、子弹、动态光照和房间清理基础，也给随机地图、武器差异、Augment 和氛围设计提供了共同目标。

第一阶段不应立刻制作完整三幕流程。先完成一个 **8-12 分钟、6 个房间、1 个 Boss、3 把武器、12 个 Augment** 的垂直切片，并用实际游玩数据决定是否扩展。

## 2. 当前项目起点

以下判断基于当前 `macos-port` 分支及仓库内设计文档。

### 已经可以支撑玩法实验的能力

- 玩家具有走、跑、跳、蹲、滑铲、空中控制和动态 FOV。
- 子弹具有连续碰撞、飞行轨迹、发光和动态光源接口。
- 敌人具有生成、追击、接触伤害、生命值和死亡状态。
- 已有玩家生命、敌人血条、准星、小地图和房间清理检测。
- 地图 JSON 已能表达 brush、出生点、敌人点、物品点、trigger 和灯光。
- `GameState` 已预留 `ROOM_CLEARED`、`PLAYER_DEAD` 和 `RunState`。
- `Map` 已支持增删与序列化，可作为房间模板工具链的基础。

### 仍然缺失的关键玩法层

- 敌人的攻击方式和战场职责不足，目前主要是接近玩家并造成接触伤害。
- 武器只有一个主要行为，没有武器定义、切换、稀有度或局内升级。
- 房间清理后没有真实奖励、路线选择或下一房间加载。
- 没有 encounter director、敌潮脚本、难度曲线或可复现随机种子。
- 没有 Augment 数据模型、标签系统和效果组合规则。
- 没有局内资源、掉落吸取、积分、统计或快速重开。
- 没有音频系统，而声音对高压 FPS 的可读性非常关键。
- 地图目前是整张 JSON；尚未形成可拼接的房间模板和连接口协议。

因此，下一步的瓶颈不是基础渲染，而是 **战斗导演、内容数据化与反馈闭环**。

## 3. 四款参考作品的设计观念

### 3.1 Devil Daggers：把少量规则压到极深

Devil Daggers 的官方描述只承诺一个清晰目标：在深渊竞技场中尽可能久地生存。它用一种武器的两种射击方式、流畅移动、敌人晶体升级、固定的生存压力和排行榜回放支撑长期重复游玩。官方明确列出圆周移动、兔子跳、武器跳、速度提升和双跳，说明移动不是便利功能，而是核心技能空间。[^1]

它最值得借鉴的并不是“难”，而是以下结构：

1. **失败具有高信息密度。** 玩家死亡后通常能指出自己漏听、漏看、走位或击杀优先级上的错误。
2. **威胁具有时间结构。** 敌人不是均匀增加，而是以能被学习和预判的组合出现。
3. **敌人是战场职责，不只是数值差异。** 追击者、生产者、远程压力源和区域封锁者共同制造优先级问题。
4. **移动和输出共用同一套掌握过程。** 高级移动既避免伤害，又改善输出角度和资源获取效率。
5. **重开成本接近零。** 失败立刻回到可操作状态，个人最佳成绩给每局提供目标。
6. **声音是战场雷达。** 低可见度不是任意剥夺信息，而是把部分信息转移到位置明确、彼此不同的声音提示。

对 Silic2 的转译：

- 每个战斗房间采用可复现的 `spawn set`，随机种子只改变有限变量，不彻底打乱威胁语法。
- 每种敌人必须拥有独立的轮廓、颜色节奏和 3D 方位音。
- 滑铲、跳跃和空中控制要参与伤害、资源或冷却循环，而不只是更快移动。
- 记录房间完成时间、受伤次数、最高连杀和整局分数；死亡后 3 秒内可以重开。
- 暂不采用一击即死。Silic2 的目标包含构筑增长，生命值应允许玩家在一局内修正少量错误。

### 3.2 Eclipsium：让美术效果改变玩家理解世界的方式

Eclipsium 的官方定位是第一人称冒险：世界持续转化，玩家自身也因牺牲与遭遇而改变；玩家通过一只会扭曲和转化的手在环境中开路。[^2] 官方商店描述强调没有安全感、每个地点都有自己的逃离路径，以及“转化之手”是持续存在的行动媒介。[^3] 开发团队也把声音和环境列为压迫感的中心，并希望世界本身具有生命感。[^4]

这带来三个比“模仿 PS1 画面”更重要的观念：

1. **视觉风格必须参与规则。** 像素化、抖动、有限颜色和形变应提示危险、隐藏路径或世界状态，而不是全程覆盖的滤镜。
2. **能力改变感知方式。** 新能力不只增加伤害，也可以让玩家看见、穿过、点燃或扭曲此前无法理解的空间。
3. **空间变化可以成为奖励。** 清理战斗后，房间发生可见且不可逆的形变，比单纯弹窗加数值更能建立世界记忆。

Eclipsium 的更新历史同时暴露了边界：开发者后来增加移动速度、冲刺，并调整像素化、屏幕震动和可见性。[^5] 这说明强风格不能牺牲移动节奏和战斗可读性。

对 Silic2 的转译：

- 将 Eclipsium 影响限制在 **异常房、幕间转化、Boss 阶段变化和环境提示**，不让所有普通战斗持续变形。
- 每个异常效果必须改变一个可描述的玩法规则，例如“红光内子弹反弹”“地面在击杀后翻转”“只有开火时能看见出口”。
- 后处理强度分层：战斗信息层保持稳定，环境层允许抖动和量化，受击或转化时才短暂突破上限。
- 音频先于重型美术资产。一个有方向、有节奏的威胁声音，比更多粒子更能形成恐惧和可读性。

### 3.3 元气骑士：把随机性包装成连续的小房间决定

元气骑士的官方商店描述强调大量英雄和武器、随机生成地牢、宝物与 NPC，以及自动瞄准带来的低输入门槛。[^6] 它的核心价值并不只是“内容多”，而是玩家频繁经历 **进房、读局面、清敌、领资源、选门、换武器** 的短循环。

ChillyRoom 的公开更新也显示，Buff 选择、固定位置的副武器刷新，以及武器和构筑标签被用于制造局内路线差异。[^7] 官方还明确提出优化 Buff 刷新机制，以减少固定顺序造成的重复并提高随机性的可控程度。[^8]

可提炼的观念是：

1. **房间是节奏标点。** 战斗之间有短暂安全期，允许玩家理解奖励和重新建立方向感。
2. **武器是行为包。** 好武器的差异来自攻击形态、风险距离和资源消耗，不只是 DPS。
3. **随机地牢应由可控模块组成。** 随机负责排列和机会，手工模板负责战斗质量。
4. **资源制造临时约束。** 能量、金币或弹药迫使玩家在高输出和可持续性之间切换。
5. **路线可见但结果不完全可知。** 玩家选择风险类型，而不是预先知道全部奖励。

对 Silic2 的转译：

- 采用“手工房间模板 + 连接口 + 有约束的房间图”，不做任意几何的完全程序生成。
- 第一版只做 3 把差异极大的武器，而不是先追求数量：连射针枪、近距散射炮、蓄力穿透器。
- 允许携带 1 把主武器和 1 个替换槽；换武器是有代价的跑内决定。
- 房间类型先限制为战斗、精英、武器库、异常、休整、Boss 六种。
- 不加入英雄职业。当前 GDD 的“空白角色”方向更适合让移动技术和构筑成为主角。

### 3.4 Vampire Survivors：让增长形成可感知的曲线

Vampire Survivors 的关键不是“自动攻击”，而是把传统 RPG 的成长压缩进单局：持续敌潮提供经验，升级提供少量随机选择，武器和被动逐步组合，最终从脆弱走向大面积控制。官方商店将其描述为具有极简玩法和 roguelite 元素的时间生存游戏。[^9]

创作者 Luca Galante 在任天堂采访中解释，系统简化的目的之一是把开发时间集中到角色和内容；30 分钟终点则来自测试中约 20 分钟开始感到厌倦，因此用明确结局维持新鲜感，而不是无限延长。[^10] 他也将重复游玩的新鲜度归因于新角色、关卡、武器的解锁，以及升级、武器和 Arcana 带来的随机应变；宝箱演出则被专门设计成与奖励价值匹配。[^10]

可提炼的观念是：

1. **增长必须经常被感知。** 玩家不能连续几分钟只看到数值缓慢累加。
2. **选择数量少，组合后果深。** 每次三选一比打开完整技能树更适合不中断动作节奏。
3. **火力成长和敌潮成长相互追赶。** 玩家不是单向碾压，而是在多个短窗口中领先或落后于威胁曲线。
4. **奖励演出负责确认阶段跃迁。** 升级、进化和稀有掉落要有不同反馈等级。
5. **局外解锁主要扩展可能性。** 更健康的长期进度是开放新武器、Augment 和规则，而不是永久堆高基础伤害。

对 Silic2 的转译：

- 保留主动开火和瞄准，这是第一人称项目的核心表达；不加入默认自动攻击。
- 普通升级放在房间结束时，避免射击过程中频繁暂停。
- 局内可以有一次“中场进化”：满足标签组合后，武器在战斗中自动进入新形态，形成高潮。
- 永久进度以横向解锁为主；初期不做永久伤害、生命和速度等级。
- 最终完整局长目标为 18-24 分钟，垂直切片先做 8-12 分钟。局长由测试中的注意力曲线决定，而不是因参考作品固定为 30 分钟。

## 4. 统一后的设计支柱

### 支柱 A：移动产生战斗价值

玩家移动不是为了从 A 到 B，而是为了维持输出窗口、吸取资源和操纵敌群。

建议基础规则：

- 敌人死亡掉落 `Shard`，停留 8-12 秒后消散。
- Shard 必须靠近拾取；高速移动扩大吸取半径或提高价值。
- 滑铲期间击杀积累 `Momentum`，Momentum 提高换弹、射速或穿透，而不是简单增加移动速度。
- 空中击杀、贴身擦过投射物和连续不落地移动可以触发少量额外收益。
- 不奖励原地绕柱或无风险拖延；房间导演会逐步压缩安全空间。

### 支柱 B：威胁可以被听懂和学会

难度来自同时处理多个明确问题，而不是随机在视野外造成伤害。

首批敌人职责：

| 敌人 | 战场职责 | 视觉/声音识别 | 玩家答案 |
|---|---|---|---|
| Chaser | 近距追击，驱赶静止玩家 | 连续低频脚步 | 滑铲拉开、穿越敌群 |
| Spawner | 持续制造小怪，是击杀优先级 | 周期脉冲和高轮廓核心 | 快速切入并爆发击杀 |
| Sentry | 远程直线压制 | 明确充能音与瞄准线 | 横移、掩体、打断 |
| Anchor | 生成减速或危险区域 | 固定节拍和地面颜色 | 改变路线、远程处理 |
| Harrier | 从侧后方短冲刺 | 左右声道尖锐提示 | 转身快照、保持空间意识 |

每个敌人首先通过单独房间教学，再进入混合编队。任何敌人首次出现时，不与另一个新敌人同时加入。

### 支柱 C：构筑改变动作，而非只改变数字

Augment 使用标签驱动：`Projectile`、`Impact`、`Movement`、`Heat`、`Void`、`Risk`。

首批 12 个 Augment 建议：

| Augment | 标签 | 行为变化 |
|---|---|---|
| Ricochet | Projectile | 子弹第一次撞墙时反弹并重新瞄向附近敌人 |
| Split Core | Projectile | 穿透目标后分裂成两枚弱弹 |
| Heavy Chamber | Impact | 射速下降，击退和伤害显著提高 |
| Aftershock | Impact | 高速命中产生小范围冲击波 |
| Slide Loader | Movement | 滑铲经过 Shard 时恢复弹药或冷却 |
| Airborne Circuit | Movement | 滞空击杀延长下一次跳跃/冲刺能力 |
| Redline | Heat/Risk | 连续射击提高射速，同时提高散布和自伤风险 |
| Cold Start | Heat | 停火后第一发冻结或强击退 |
| Blood Pickup | Risk | Shard 可回血，但拾取范围缩小 |
| Last Chamber | Risk | 低生命时最后一发自动穿透 |
| Void Mark | Void | 命中标记，击杀标记目标牵引周围敌人 |
| Eclipse | Void | 黑暗区域内伤害提高，但小地图暂时失效 |

设计约束：

- 每个 Augment 至少改变一种可见行为。
- 同一效果的纯数值等级最多 3 级。
- 三选一中至少有一个与当前武器标签兼容。
- 第三次选择前，玩家应能用一句话描述自己的构筑方向。
- 强组合可以“破坏平衡”，但必须保留瞄准、走位或资源回收中的至少一种操作压力。

### 支柱 D：房间图控制节奏，异常改变记忆

地图自动生成应分成两层：

1. **房间图生成：** 决定节点顺序、分支、风险和奖励。
2. **模板实例化：** 从人工制作并验证过的 JSON 房间池中选择模板，按 socket 连接。

第一版禁止运行时生成任意 brush 几何。自由几何生成会同时扩大导航、碰撞、可读性、灯光和内容验证成本，而当前项目最需要验证的是玩法循环。

建议单幕结构：

```text
起点
  -> 普通战斗
  -> [精英 | 武器库]
  -> 普通战斗
  -> [异常 | 休整]
  -> Boss
```

每次只向玩家展示下一层 2-3 个节点。节点图负责策略，房间内保持连续高强度动作。

异常房不是独立小游戏集合，而是对已有战斗规则的一次扭曲：

- **Only When Firing：** 只有开火时能看见墙与出口。
- **Red Reflection：** 红光区域内子弹和敌弹都会反弹。
- **Living Floor：** 每次敌潮结束后，地面高度重新组合。
- **Sacrifice Gate：** 放弃当前生命、武器等级或一个 Augment，换取稀有规则改变。

### 支柱 E：短局、快速失败、明确余味

垂直切片目标局长：8-12 分钟。完整版本目标局长：18-24 分钟。

一局的情绪曲线应是：

| 阶段 | 时间占比 | 玩家感受 |
|---|---:|---|
| 建立 | 0%-15% | 理解初始武器和本局种子 |
| 成形 | 15%-45% | 构筑出现第一组明确联动 |
| 压迫 | 45%-70% | 敌潮一度追上玩家火力 |
| 失控 | 70%-90% | 构筑完成，画面与声音达到峰值 |
| 考试 | 90%-100% | Boss 检查移动、目标优先级与构筑缺口 |

结算页只展示能指导下一局的内容：死亡来源、最高威胁、构筑标签、房间时间、受伤次数、最高连杀、个人最佳差值和本局解锁。

## 5. 推荐核心循环

### 秒级循环：3-10 秒

1. 通过声音和轮廓识别最高优先级威胁。
2. 用跑、跳、滑铲制造射击角度。
3. 主动瞄准并选择持续射击或高价值爆发。
4. 穿过危险区域收取即将消失的 Shard。
5. 利用 Shard、Momentum 和 Augment 反馈进入下一次攻击窗口。

### 房间循环：45-90 秒

1. 入场后 2-3 秒读取空间。
2. 门锁定，第一组敌人建立本房间主题。
3. 第二组敌人组合职责并压缩安全区。
4. 最后一组加入精英或环境规则变化。
5. 房间清空，玩家从三项奖励中选一项。
6. 在 15 秒内选择下一个节点并进入下一房间。

### 单局循环：8-24 分钟

1. 选择初始武器或接受每日种子配置。
2. 在房间图上选择风险与奖励类型。
3. 通过 Shard 和房间奖励构筑武器。
4. 在异常节点接受规则变化或牺牲。
5. 击败 Boss，解锁新的横向内容。
6. 查看失败信息或成绩，一键重开。

## 6. 三个玩法原型及选择门槛

不要直接实现完整 GDD。先制作三个共享资产的原型，通过测试决定主结构。

### 原型 A：Pressure Arena

**目的：** 验证 Devil Daggers 式纯战斗是否足以支撑游戏。

- 单个竞技场。
- 5 分钟固定敌潮。
- 3 种敌人、1 把双模式武器。
- Shard 拾取和 3 次固定 Augment 选择。
- 计时、快速重开、个人最佳。

通过条件：

- 新玩家第二局的平均存活或得分明显高于第一局。
- 玩家能准确描述至少两种敌人的声音和优先级。
- 玩家死亡后愿意在 10 秒内主动重开。
- 即使没有局外解锁，测试者仍愿意连续进行 3 局。

### 原型 B：Room Run（推荐主结构）

**目的：** 验证房间节奏、路线选择和构筑是否能与高速 FPS 共存。

- 6 个房间，8-12 分钟。
- 2 选 1 的简化节点图。
- 5 种敌人、3 把武器、12 个 Augment。
- 1 个武器库、1 个异常房、1 个 Boss。
- 房间模板由固定 JSON 选择，首版不要求几何拼接动画。

通过条件：

- 80% 以上的测试者能在第三个房间前描述自己的构筑。
- 房间之间的选择耗时中位数低于 20 秒。
- 同一测试者两局的路线或构筑至少有一个实质差异。
- 战斗中没有超过 8 秒的无目标寻找时间。
- 测试者认为失败主要来自可理解的战斗决定，而非看不清或随机受击。

### 原型 C：Corruption Passage

**目的：** 验证 Eclipsium 式环境异变是否增强身份，而非妨碍战斗。

- 使用与原型 B 相同的一条路线。
- 加入两种异常规则、一次空间转化和一项牺牲选择。
- 提供后处理强度开关，比较可读性。

通过条件：

- 测试者能回忆并描述异常房，而不是只记得视觉噪声。
- 异常发生后 10 秒内能理解新规则。
- 开启效果不会显著提高“未理解伤害来源”的比例。
- 异常房的完成时间不超过对应普通房的 1.5 倍，除非它明确提供更高奖励。

主结构决策：如果原型 B 的重复游玩意愿高于 A，同时 C 不损害可读性，则采用 B 作为主体、A 作为挑战模式、C 作为稀有节点语言。

## 7. 实施阶段

工期以单人有效开发日估算，不包含大规模原创美术和音乐制作。

### Phase 0：测量与快速重开（2-3 日）

交付内容：

- `RunStats`：局时、房间时长、击杀、受伤来源、移动距离、滑铲时间、Shard 拾取率。
- 固定随机种子和控制台输出。
- 死亡结算与 3 秒内重新开始。
- Debug overlay：敌人数、敌潮阶段、玩家 DPS、帧时间。

验收：同一种子可复现敌潮顺序；一局结束后能回答玩家为何死亡、在哪个阶段掉队。

### Phase 1：Pressure Arena（5-7 日）

交付内容：

- `EncounterDirector` 和 JSON 敌潮时间线。
- Chaser、Spawner、Sentry 三种敌人。
- 每种敌人的独立声音接口和清楚的攻击预警。
- Shard 掉落、消失、拾取和 Momentum 联动。
- 一把双模式基础武器。

验收：完整 5 分钟曲线可运行；敌潮无需随机也具有重复挑战价值；第二局能体现学习。

### Phase 2：构筑闭环（5-8 日）

交付内容：

- `AugmentDefinition`、标签、稀有度、冲突与前置条件。
- 房间后 3 选 1、一次 reroll。
- 首批 12 个 Augment。
- 3 把行为不同的武器。
- 构筑摘要和奖励反馈层级。

验收：至少存在 4 组可辨识协同；任何奖励选择都不会完全不适用于当前构筑；效果堆叠有上限和测试覆盖。

### Phase 3：Room Run 与受控地图生成（7-10 日）

交付内容：

- `RoomTemplate`：入口、出口 socket、边界、敌人区域、奖励点和标签。
- `RoomGraphGenerator`：按种子生成节点图，并验证起点到 Boss 可达。
- 房间加载、门锁、清理、卸载和过渡。
- 六种节点类型中的战斗、精英、武器库、休整和 Boss；异常先使用占位规则。
- 6 个经过人工验证的房间模板。

验收：1000 个自动生成的图都可达、没有连续两个休整/Boss、奖励预算合法；连续完成两局无状态泄漏。

### Phase 4：异常与感官身份（5-7 日）

交付内容：

- 两种异常规则和一个 Boss 空间变化。
- 战斗、环境、反馈三层后处理强度。
- 方向音和威胁混音优先级。
- 可关闭的屏幕震动、色差和高强度像素化。

验收：异常可在 10 秒内被理解；可访问性设置不会移除必要信息；低分辨率下敌人轮廓仍可识别。

### Phase 5：垂直切片内容与平衡（10-15 日）

交付内容：

- Harrier、Anchor 和 1 个 Boss。
- 6 个完整房间、3 把武器、12 个 Augment 的最终表现。
- 简化节点图、结算页和横向解锁。
- 8-12 分钟完整流程。
- 至少 5 名外部测试者的两轮测试。

验收：达到原型 B 的全部通过条件；没有单一武器或 Augment 在大多数种子中成为必选；Mac 和 Windows 使用相同种子时生成相同节点图和敌潮。

## 8. 建议的数据与代码边界

建议逐步建立独立于渲染层的 `game` 目录：

```text
include/game/
  run_controller.h
  run_stats.h
  encounter_director.h
  room_graph.h
  reward_draft.h
  augment.h
  weapon_definition.h

src/game/
  ...

res/gameplay/
  encounters/
  rooms/
  weapons/
  augments/
  run_rules.json
```

职责边界：

- `App` 只协调状态，不保存具体奖励和敌潮规则。
- `EncounterDirector` 输出生成命令，不直接创建 OpenGL 资源。
- `EnemyManager` 管实体生命周期，不决定整局难度曲线。
- `Weapon` 执行当前实例行为；静态参数来自 `WeaponDefinition`。
- `AugmentSystem` 通过明确事件修改行为，例如 `onFire`、`onHit`、`onKill`、`onPickup`、`onSlide`。
- `RoomGraphGenerator` 只生成逻辑图；`Map` 继续负责几何和实体数据。
- 随机数统一由 run seed 派生子流，禁止各系统独立使用全局随机设备。

敌潮定义示例：

```json
{
  "id": "arena_intro_01",
  "duration": 75,
  "events": [
    { "time": 0, "enemy": "chaser", "count": 4, "zone": "front_arc" },
    { "time": 12, "enemy": "sentry", "count": 1, "zone": "far_edge" },
    { "time": 26, "enemy": "spawner", "count": 1, "zone": "side_edge" }
  ]
}
```

房间模板至少需要：

- 唯一 ID 与难度标签。
- 入口/出口 socket 的位置、朝向和类型。
- 玩家安全出生体积。
- 敌人生成 zone，而不是只有固定点。
- 导航和碰撞验证边界。
- 灯光配置与环境规则标签。
- 适用敌群、禁止敌群和最大实体预算。

## 9. 平衡框架

### 威胁预算

不要只按敌人数量控制难度。每个敌人应有四项成本：

- `attentionCost`：需要多少视线和声音注意力。
- `spaceCost`：压缩多少可移动区域。
- `damagePressure`：不处理时造成多快的失败。
- `targetPriority`：是否迫使玩家中断当前目标。

每个敌潮拥有总预算和同类上限。例如两个 Spawner 的数值成本可能不高，但 target priority 叠加后会让其他选择失去意义，因此必须单独限额。

### 玩家强度

用可观察量评估构筑，而不是只计算理论 DPS：

- 单目标击杀时间。
- 3 秒范围伤害。
- 空间控制面积。
- Shard 回收效率。
- 移动状态覆盖率。
- 生存恢复能力。

导演根据房间序号和节点风险决定预算，不根据玩家即时表现暗中作弊。若需要动态调整，只改变下一房间的备选敌潮，不修改已出现敌人的生命和伤害。

### 随机性

- 重要随机结果必须由 seed 复现。
- 选择随机性采用权重、标签兼容和防重复抽取。
- 连续两次奖励不能全是已有效果的纯数值升级。
- 每局至少保证一次武器选择和一次构筑核心选择。
- 稀有奖励可以惊喜，但不能是完成基础构筑的唯一入口。

## 10. 测试指标与决策记录

每轮测试至少记录：

| 指标 | 初始目标 | 说明 |
|---|---:|---|
| 首次有意义选择时间 | < 90 秒 | 太晚会让开局重复 |
| 平均战斗房时长 | 45-90 秒 | 超过后容易失去房间节奏 |
| 无目标时间 | 单段 < 8 秒 | 反映生成、导航或可读性问题 |
| 死亡到可操作重开 | < 3 秒 | 支撑技能学习循环 |
| 第三次奖励后的构筑识别率 | > 80% | 玩家能描述本局玩法 |
| 未理解伤害来源比例 | < 15% | 高于此值先修反馈，不调数值 |
| Shard 平均回收率 | 60%-85% | 太高无风险，太低令人放弃 |
| 同种子第二局成绩改善 | > 10% | 检查失败是否可学习 |
| 完成后主动再开一局比例 | > 50% | 小样本方向指标，不作商业预测 |

每个玩法改动写一张简短实验卡：

```text
假设：滑铲拾取恢复冷却会让玩家主动穿越敌群。
改动：滑铲期间每拾取 5 个 Shard，恢复 15% 副射击冷却。
观察：滑铲时间、近敌拾取率、受伤率、玩家口述策略。
保留条件：移动选择增加，且未成为无脑循环。
```

不要仅以“好不好玩”记录测试。保留玩家行为、口述原因和设计者解释三列，防止结果被单一印象主导。

## 11. 风险与非目标

### 主要风险

1. **低分辨率破坏敌人可读性。** 先建立轮廓、颜色和声音规范，再增加敌人数量。
2. **构筑增长消灭 FPS 技巧。** 强效果可以减少瞄准精度要求，但不能同时消除走位、目标选择和资源风险。
3. **房间结构打断高压节奏。** 奖励与路线界面必须短，普通房之间不放长叙事段落。
4. **异常视觉造成疲劳。** 只在特定节点和短时间使用高强度效果，并提供独立强度设置。
5. **程序生成扩大验证成本。** 首版只组合手工房间，不生成任意几何。
6. **内容数量掩盖基础问题。** 在 3 把武器和 12 个 Augment 尚未形成多种策略前，不扩大池子。
7. **永久成长破坏难度标尺。** 局外系统先解锁选项，不提高基础数值。
8. **没有音频仍继续堆画面。** Sentry 和 Spawner 完成方向音之前，不应进入大规模混合敌潮。

### 当前明确不做

- 自动攻击作为默认战斗方式。
- 任意多边形的完整程序地图生成。
- 数百件低差异武器。
- 多英雄职业系统。
- 在线排行榜和完整 replay 系统；先保留 seed 与本地统计接口。
- 大规模永久属性树。
- 在玩法垂直切片前投入完整地图编辑器 GUI。
- 连续四小时线性叙事流程。

## 12. 第一批开发任务

按依赖顺序执行：

1. 建立 `RunStats`、固定 seed、快速重开和 Debug overlay。
2. 将敌人参数从硬编码拆成数据定义，并实现 Chaser、Spawner、Sentry。
3. 建立 JSON `EncounterDirector`，完成 5 分钟固定 Pressure Arena。
4. 加入 Shard、消失时间、拾取半径和滑铲联动。
5. 把当前武器改成数据驱动的双模式基础武器。
6. 实现事件式 Augment 接口与 6 个最小 Augment。
7. 做第一次内部测试，决定是否继续扩展为 Room Run。
8. 增加另外 2 把武器和剩余 6 个 Augment。
9. 定义 room socket 和模板验证器，再实现房间图生成。
10. 最后加入异常房、空间变化和牺牲选择。

第一道正式决策门应设在任务 7。若单竞技场的移动、威胁识别和拾取循环尚不成立，不进入地图生成；地图无法挽救不成立的战斗。
